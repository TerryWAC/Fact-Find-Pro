# Future Perfect Mortgage FactFind (per-link question-set variant)

Tom Hunt (Future Perfect, tom.h@theopenworkpartnership.com) asked for changes to his Mortgage FactFind on 26 October 2026. His form was never the standard Mortgage questionnaire: Version 1 ran from his own Typeform, "Tom Hunt - Mortgage" (`qd0zpSvg`, created 20 August 2026), which already had loans, credit cards, additional properties, a connected-sale page, a monthly budget question and general insurance that the standard form did not (loans and credit cards have since been added to the standard form for everyone). The change request is written against that form.

The platform therefore gained **question-set variants**: a FactFind link can name a bespoke schema while staying the same FactFind type everywhere else. Nothing changes for any other adviser.

## How a variant is attached

- `factfind_forms.variant` (migration `20261111120000_form_variants.sql`) names the question set a link serves; null is the standard form. `resolve_factfind_form` returns it with the link.
- The registry (`src/lib/forms/registry.ts`) maps `variant → type → schema`. `getFormSchema(type, variant)` falls back to the standard schema for unknown variants or types the variant does not cover.
- The public page, the admin preview, and server-side validation in `submitFactFind` all take the schema from the link. The client never chooses a schema.
- Submissions record the variant schema's `schema_version`. Client PDFs and emails find the internal sections through `getSchemaForSubmission`, so adviser-only pages stay out of client copies for bespoke submissions too.
- The adviser's links page shows "Your question set" on a bespoke link; the admin's prepared-adviser page shows "Bespoke questions".

Only Tom Hunt's **mortgage** link carries `variant = 'future_perfect'`. His Protection, Medical and Home links, and every other adviser's links, serve the standard questionnaires. To attach or detach a variant, update that one row:

```sql
update public.factfind_forms set variant = 'future_perfect'
where form_type = 'mortgage'
  and adviser_id = (select id from public.profiles where lower(email) = 'tom.h@theopenworkpartnership.com');
```

## The schema

`src/lib/forms/schemas/mortgage-future-perfect.json` is generated by `npm run build:variants` (`scripts/build-mortgage-future-perfect.mjs`) and checked by `npm run verify:variants` in CI. Do not hand-edit the JSON. The script takes Future Perfect's wording from `tests/fixtures/typeform/future-perfect-mortgage.json` (the live Typeform definition read on 11 November 2026, questions only, no responses) and shared question definitions from the standard Mortgage schema, then applies the change request. Version `2026.11-future-perfect.1`, 19 sections, 198 fields.

The standard Typeform comparison (`npm run verify:typeforms`) is unaffected: the four standard schemas still match their captured originals. (Since 11 November 2026 the standard Mortgage form also asks the loans and credit-card questions for every adviser, as documented in `tests/fixtures/typeform/README.md`; the bespoke form already had them on its own pages.)

## The change request, item by item

| Request | Done as |
| --- | --- |
| Remove Adviser Name | Removed. The server already attributes every submission to the adviser who owns the link. |
| Date of Appointment, Source and "Other" on one page | One adviser-only section, "Internal Details". |
| Nationality from Health to Personal Details | Moved for both applicants; health keeps smoker, height, weight and serious health issues. |
| Dependant date of birth; remove gender; adult dependants | Date of birth added, gender removed from the fields and the further-dependants prompt, wording is "children or other dependants". |
| Delete Monthly Expenses | Section removed entirely. |
| Loans routing | "Do you have any loans?" = Yes shows the four loan detail blocks first, then the additional-loans box, on one page. |
| Credit cards: large optional box | "Further cards or additional information", after card 3. |
| Credit issues | CCJ and bankruptcy questions replaced by "Are there any credit issues?" and, if Yes, a large "Please provide details of all credit issues." box. |
| Existing properties before Purchase/Remortgage | "Do you own any properties?" then one Property 1 page: address, estimated value, mortgage outstanding, current lender, buy-to-let Yes/No, rental income when buy-to-let, large notes. Then "Do you own any other additional properties?" with one large box for all of them. |
| Purchase, connected sale, one sale page | "Is there a sale connected to the purchase?" on the purchase page. The sale page holds address, value, outstanding, lender, rate, term remaining, product expiry, early repayment charges (Yes/No/Not known with a details box), sale position and sale notes together. |
| Carry an existing property across | "Which property is being sold?" offers Property 1; choosing it copies its address, value, outstanding balance and lender into the sale fields, which stay editable. Choosing "A different property" leaves the fields as they are. |
| Monthly surplus | The surplus question replaces the budget question and appears, as a monetary field, on both the purchase and remortgage pages. |
| Other Mortgage Details | "Mortgage Costs (£)" becomes a large "Other Mortgage Details" box with stamp duty, fees, legal costs and surveys in its help text. |
| Solicitor | New section after the mortgage pages: Yes shows firm, contact, email and telephone; No shows an optional recommendation-notes box. |
| Plans and Future Changes | Renamed and placed immediately after Solicitor. |
| Other Employment Benefits | New section after Sick Pay with a large box per applicant (Applicant 2 on joint cases). |
| Pensions, investments and savings | Opening question widened; a large "Pensions, Investments and Savings — Details" box appears for anyone answering Yes, whatever the review answers say. The review and happiness questions are otherwise unchanged. |
| General insurance on one page | Provider, renewal date, premium and frequency together. |
| "Not known" answers | A Not known choice on sick pay, existing protection, the mortgage-cover question and pensions/investments/savings; "Not known" is accepted in the general insurance text fields, and the renewal date may be left blank. |
| Delete Section 13 Admin Notes | Removed entirely. |
| Free text without restrictive limits | All new boxes are large and no character limit is applied anywhere in the form. |

Small corrections made in passing, all reported here rather than silently: the remortgage page's first field, titled "Purchase amount" in the Typeform, is labelled "Estimated value"; "balamce" is spelled "balance"; the Typeform's required flags are kept (only the declaration), plus the client's name and email that every submission needs.

## Tests

- `tests/unit/future-perfect-schema.spec.ts` checks the schema is well formed and asserts each item above against the generated JSON, and that the registry serves the variant only when asked.
- `tests/e2e/future-perfect-mortgage.spec.ts` completes a purchase with a connected sale through the preview's `bespoke` link, including the Property 1 carry-across, and confirms the submission records the variant version while the standard link is unchanged.
